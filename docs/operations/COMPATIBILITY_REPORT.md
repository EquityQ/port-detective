# Compatibility Reports

Language / 语言: English below · [中文摘要](#中文摘要) · [Documentation index / 文档中心](../README.md)

Use the GitHub **Compatibility report** issue form for a reproducible platform-specific result. Search existing reports first. Do not include credentials, personal command lines, or private paths.

Reports should identify the exact environment and distinguish a confirmed incompatibility from a permission or network-namespace limitation. Maintainers can label reports by OS, architecture, runtime, CLI version, and permission level; resolved reports should link to the fixing commit or release.

## Report details

```text
CLI version or commit:
Operating system and version:
Architecture:
Go version (source builds):
Python version (if applicable):
Node.js version (if applicable):
Shell and terminal:
Permission level (standard/admin/root):
WSL, container, VM, VPN, or sandbox:
Listener address family (IPv4/IPv6/unknown):
Command or minimal SDK call:
Expected result:
Actual result and sanitized output:
Can the issue be reproduced? How often?
```

## 兼容性报告

请使用 GitHub **Compatibility report / 兼容性报告** 表单提交可复现的平台问题，并先搜索已有报告。不要附带凭据、个人命令行或私有路径。

报告应列出精确环境，并区分已确认的不兼容与权限、网络命名空间限制。维护者可按操作系统、架构、运行时、CLI 版本和权限级别分类；问题解决后应链接修复提交或版本。

```text
CLI 版本或提交：
操作系统及版本：
架构：
Go 版本（源码构建时）：
Python 版本（如适用）：
Node.js 版本（如适用）：
Shell 和终端：
权限级别（普通用户/管理员/root）：
WSL、容器、虚拟机、VPN 或沙箱：
监听地址族（IPv4/IPv6/未知）：
命令或最小 SDK 调用：
预期结果：
实际结果及脱敏输出：
能否复现及复现频率：
```
